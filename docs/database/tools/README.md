# 数据建模工具到物理建表

本项目使用 **dbdiagram.io** 作为辅助数据建模工具：物理建表脚本不是手写的，而是由 dbdiagram.io 的 DBML（`docs/database/dbml/class_test_full.dbml`）导出生成，再执行到物理数据库中。

## 一、建模与导出链路

```text
业务需求
  └─ DBML 模型文件：docs/database/dbml/class_test_full.dbml
       ├─ 方式 A：粘贴到 https://dbdiagram.io/d，右侧可视化建模
       │          再用 Export → SQL 导出 Oracle / MySQL / PostgreSQL 脚本
       └─ 方式 B：使用 dbdiagram.io 官方 DBML CLI 导出
                  npx @dbml/cli dbml2sql class_test_full.dbml --oracle   -o schema-oracle-dbml.sql
                  npx @dbml/cli dbml2sql class_test_full.dbml --mysql    -o schema-mysql-dbml.sql
                  npx @dbml/cli dbml2sql class_test_full.dbml --postgres -o schema-postgres-dbml.sql
  └─ 物理建表：把导出的 SQL 执行到物理数据库
       ├─ Oracle（默认物理库）：backend/src/main/resources/db/schema-dbml-oracle.sql
       │    dbdiagram.io Oracle 方言 + Oracle 原生类型适配
       └─ H2 文件库（离线回退）：backend/src/main/resources/db/schema-dbml-h2.sql
```

## 二、本仓库中由 dbdiagram.io 导出的 SQL

| 文件 | 说明 |
| --- | --- |
| `sql/dbdiagram-export/dbml_export_oracle.sql` | dbdiagram.io DBML 引擎导出的 Oracle 方言 DDL（27 张表） |
| `sql/dbdiagram-export/dbml_export_mysql.sql` | 同上，MySQL 方言 |
| `sql/dbdiagram-export/dbml_export_postgres.sql` | 同上，PostgreSQL 方言 |
| `sql/schema-dbml-oracle.sql` | Oracle 方言 + 原生类型适配后的物理建表脚本（默认使用） |
| `sql/schema-dbml-h2.sql` | PostgreSQL 导出 + H2 兼容处理（去掉 `DEFERRABLE INITIALLY IMMEDIATE`），离线回退使用 |
| `backend/src/main/resources/db/schema-dbml-oracle.sql` | 应用启动引导使用的 Oracle 建表脚本 |
| `backend/src/main/resources/db/schema-dbml-h2.sql` | 应用启动引导使用的 H2 建表脚本 |

导出结果：27 个 `CREATE TABLE`、41 个外键、9 个复合唯一约束，字段、注释、默认值和 DBML 一致。

### Oracle 方言的原生类型适配

dbdiagram.io 的 Oracle 导出保留 DBML 通用类型，落到 Oracle 前做一次等价替换（`sql/schema-dbml-oracle.sql` 已处理）：

| DBML / 导出类型 | Oracle 类型 |
| --- | --- |
| `bigint` | `NUMBER(19)` |
| `int` | `NUMBER(10)` |
| `varchar(n)` | `VARCHAR2(n)` |
| `decimal(p,s)` | `NUMBER(p,s)` |
| `text` | `CLOB` |
| `GENERATED AS IDENTITY` | `GENERATED BY DEFAULT AS IDENTITY` |

带引号的小写标识符保持不变，因此 Hibernate 侧开启 `globally_quoted_identifiers` 与之匹配。

## 三、物理库说明

当前默认物理库是 **Oracle AI Database 26ai Free**（容器 `gvenzl/oracle-free:23-slim-faststart`，服务名 `FREEPDB1`，业务 schema `life_circle`）：

- 表由 `OracleSchemaBootstrapRunner` 在首次启动时执行 dbdiagram.io 导出的脚本创建；
- `spring.jpa.hibernate.ddl-auto=none`，Hibernate 不参与建表；
- 应用默认 profile 即 `oracle`（`application.yml` 中 `spring.profiles.active=oracle`）。

没有 Oracle 环境时可用 H2 回退：

```powershell
mvn -f backend/pom.xml spring-boot:run "-Dspring-boot.run.profiles=h2file"   # 文件库
mvn -f backend/pom.xml spring-boot:run "-Dspring-boot.run.profiles=h2"       # 内存库
```

单元测试使用 `backend/src/test/resources/application.yml` 的 H2 内存库，不依赖 Oracle。

## 四、复现步骤

```powershell
# 1. 安装 Node.js 后，用官方 CLI 从 DBML 导出 DDL（或直接在 dbdiagram.io 网页导出）
npx @dbml/cli dbml2sql docs/database/dbml/class_test_full.dbml --oracle -o schema-oracle-dbml.sql

# 2. Oracle 原生类型适配：bigint→NUMBER(19)、text→CLOB、varchar→VARCHAR2、
#    decimal→NUMBER、GENERATED AS IDENTITY→GENERATED BY DEFAULT AS IDENTITY
#    处理结果放到 backend/src/main/resources/db/schema-dbml-oracle.sql

# 3. 启动应用，首次启动用该脚本在 Oracle 建表并写入演示数据
mvn -f backend/pom.xml spring-boot:run "-Dspring-boot.run.profiles=demo" ^
  "-Dspring-boot.run.arguments=--spring.main.web-application-type=none --persistence.exit-after-demo=true"
```

第二次用同一命令启动时，应用检测到物理表已存在，不再建表；检测到已有数据，不再写入，只输出每张表的行数，用于验证数据确实保存在 Oracle 中。
