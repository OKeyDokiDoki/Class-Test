Oracle 物理建表与数据持久化验证记录
====================================

项目：城市15分钟便民生活圈与小微开店智能助手
日期：2026-10-27
数据库：Oracle AI Database 26ai Free Release 23.26.3.0.0（容器 gvenzl/oracle-free:23-slim-faststart）
服务名：FREEPDB1（jdbc:oracle:thin:@localhost:1521/FREEPDB1）
业务 Schema：LIFE_CIRCLE

一、建表来源
DBML：docs/database/dbml/class_test_full.dbml
导出：docs/database/sql/dbdiagram-export/dbml_export_oracle.sql（dbdiagram.io Oracle 方言）
适配：Oracle 原生类型替换后写入
      backend/src/main/resources/db/schema-dbml-oracle.sql
      - bigint            -> NUMBER(19)
      - int               -> NUMBER(10)
      - varchar(n)        -> VARCHAR2(n)
      - decimal(p,s)      -> NUMBER(p,s)
      - text              -> CLOB
      - GENERATED AS IDENTITY -> GENERATED BY DEFAULT AS IDENTITY
      结果：27 张表、41 个外键、9 个复合唯一约束、27 个身份列
执行者：OracleSchemaBootstrapRunner（@Profile("oracle")，首次启动执行，表存在则跳过）
约束：spring.jpa.hibernate.ddl-auto=none，Hibernate 不参与建表

二、第一次启动（创建物理表 + 写入数据）
命令：
  mvn -f backend/pom.xml spring-boot:run "-Dspring-boot.run.profiles=oracle,demo" ^
    "-Dspring-boot.run.arguments=--spring.main.web-application-type=none --persistence.exit-after-demo=true"

输出：
  [schema] 已按 dbdiagram.io DBML 导出脚本在 Oracle 创建物理表
  [demo] 首次启动：已向物理数据库写入演示数据
  [demo] 物理数据库各表行数：27 张表各 1 行

三、第二次启动（进程重启，读回数据）
输出：
  [schema] Oracle 物理表已存在，跳过建表
  [demo] 再次启动：数据库中已有数据，跳过写入
  [demo] 物理数据库各表行数：与第一次一致

四、REST 接口写入持久化验证
  POST /api/merchant/intents  -> {"id":2,"status":"submitted",...}
  GET  /api/merchant/intents  -> 2 条记录
进程重启后再统计：
  merchant_intent = 2
说明接口写入 Oracle 的数据在应用重启后仍然存在。

五、默认配置
application.yml 中 spring.profiles.active=oracle，直接运行
  mvn -f backend/pom.xml spring-boot:run
即连接 Oracle；无 Oracle 环境时用 -Dspring-boot.run.profiles=h2 或 h2file 回退。
单元测试使用 backend/src/test/resources/application.yml 的 H2 内存库，不依赖 Oracle。
