# 项目架构

## 开发原则

第一阶段优先完成可演示、可解释、可替换的业务闭环。地图、人口栅格、POI 与大模型均通过服务层隔离，课程开发期间可以先用模拟数据，后续再接真实平台。

## 模块划分

| 模块 | 当前实现 | 后续接入 |
| --- | --- | --- |
| 地图展示 | 轻量示意地图 | 高德地图 JS API |
| 步行圈 | 固定 15 分钟范围演示 | 高德步行路径规划与等时圈 |
| POI 分析 | 后端演示数据 | 高德 Web 服务或开放数据 |
| 人口栅格 | 候选点人口指数 | 政务开放数据或栅格文件 |
| 智能建议 | 规则模板 | LangChain4j + 大模型 API |
| 数据库 | H2 内存数据库 | Oracle Free 或正式 Oracle |

## 前端页面

- 居民端：画像、便利度总分、五维雷达图、设施清单与改善建议。
- 商户端：业态与预算筛选、候选点排序、需求缺口和一键提报。
- 社区端：片区短板、招商匹配、网点增设模拟与统计概览。

## 后端接口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 服务状态 |
| GET | `/api/resident/assessment` | 居民生活圈体检 |
| GET | `/api/merchant/recommendations` | 商户选址推荐 |
| POST | `/api/merchant/intents` | 提交开店意向 |
| GET | `/api/community/overview` | 社区综合概览 |
| POST | `/api/community/simulations` | 模拟新增网点 |

## 推荐迭代顺序

1. 完成高德地图展示与点选坐标。
2. 将居民评估接口接入真实 POI。
3. 设计 Oracle 表并导入人口、设施和商户数据。
4. 接入 LangChain4j，先实现结构化建议生成。
5. 增加登录、权限和社区工作台。
